AI × 業務改善 × GAS Automation

AIで「作れる」は当たり前。 現場で「回り続ける」仕組みをつくる。

バックオフィス・カスタマーサポートの実務を起点に、 課題整理、自動化、運用、監視、改善まで。 「機能を増やすこと」ではなく「現場の手間を減らすこと」を目的に設計しています。

改善事例を見る 運用・保守設計を見る
Philosophy

つくって終わりではなく、「使われ続ける」まで。

自動化は、正常に一度動けば完成ではありません。 業務量の増加、担当者変更、データ不備、APIエラー、タイムアウトなど、 実運用で起こることまで含めて考えます。

Case Studies

CASE 01

週次報告要約Bot

AI要約 / GAS / Trello

Problem

週次報告の確認が分散し、管理側が毎回すべてを読み込む必要がありました。

Thinking
単純にAIで要約するのではなく、「管理者が何を確認したいか」を先に定義し、 重要項目を標準化したうえで要約・数値化する設計にしました。

Flow

週次報告
→
GAS取得
→
AI要約
→
重要項目抽出
→
Trello連携

Result

確認時間 60分 → 20分。約67%削減。

CASE 02

配送管理の自動化

Forms / GAS / Chatwork API

Problem

フォーム回答後、人が確認・転記・通知する工程があり、深夜や休日の回答では見落としリスクが残っていました。

Thinking
「確認を速くする」のではなく、 「人が確認しなければ配送されない構造」そのものをなくす方向で設計しました。

How I Think

機能より先に、現場を見る。

01

作業を速くする前に、作業自体をなくせないか考える。

「効率化」ではなく、そもそもその確認・転記・連絡が必要なのかから見直します。

02

うまくいく時だけでなく、想定外にも強い仕組みをつくる。

タイムアウト、APIエラー、データ不備など、実運用で起こる失敗まで設計対象にします。

03

自分しか触れない仕組みにしない。

担当変更や引き継ぎがあっても運用できるよう、構造・ログ・手順を整理します。
